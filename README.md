# autoFormat

![Tests](https://github.com/oydabik/autoFormat/actions/workflows/tests.yml/badge.svg)
![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)

Автоматическое форматирование студенческих отчётов `.docx` → `.docx`.

Программа читает отчёт, распознаёт блоки и применяет к ним фиксированные стили.

## Возможности

- Распознавание блоков документа (титульная часть, задачи, код, картинки, списки).
- Применение фиксированных стилей к каждому типу блока.
- Автоматическая вставка пустых строк между группами блоков.
- Извлечение картинок из `.docx` и масштабирование.
- CLI с флагами `--verbose` и `--quiet`.
- Логирование с уровнями (DEBUG / INFO / WARNING / ERROR).

## Установка

Требуется Python 3.10+.

```bash
pip install python-docx
```

## Использование

Базовый запуск:

```bash
python cli.py input.docx output.docx
```

С DEBUG-логами:

```bash
python cli.py input.docx output.docx -v
```

Только предупреждения и ошибки:

```bash
python cli.py input.docx output.docx -q
```

Справка:

```bash
python cli.py --help
```

## Архитектура

Проект разбит на модули с односторонними зависимостями:

```
models ◀── config ◀── generator ◀── cli
       ◀── spacing ◀──┘
```

- `models.py` — dataclass'ы и enum'ы: `ParagraphStyle`, `BlockKind`, `Block`.
- `config.py` — стили и паттерны: `ReportConfig`, `LIST_ITEM_PATTERN`.
- `spacing.py` — правила пустых строк: `SpacingRules`.
- `generator.py` — чтение, классификация и рендер: `ReportGenerator`.
- `cli.py` — точка входа, разбор аргументов через `argparse`.

## Структура отчёта

Одна «задача» в отчёте выглядит так:

```
[SECTION]    Задача N. текст задачи
[SUBHEADER]  Решение.
[SUBHEADER]  Скриншоты
[IMAGE]      картинка 1
[IMAGE]      картинка 2
             ↓ пустая строка (генерируется)
[SUBHEADER]  Исходный код
[CODE]       код
             ↓ пустая строка (генерируется)
[SECTION]    Выводы
[LIST_ITEM]  1. ...
[LIST_ITEM]  2. ...
[LIST_ITEM]  3. ...
             ↓ пустая строка (генерируется)
[SECTION]    Задача N+1. текст следующей задачи
```

Отчёт начинается с титульной части (`TITLE`), затем идёт одна или несколько
таких задач подряд.

## Стили абзацев

| Стиль        | Применяется к                                | Выравн. | Шрифт       | Разм. | Интерв. | До/после | Left     | First line |
|--------------|----------------------------------------------|---------|-------------|-------|---------|----------|----------|------------|
| `TITLE`      | титульная часть                              | center  | TNR         | 14    | 1.5     | 0        | 0        | 0          |
| `SECTION`    | `Задача N.`, `Выводы`                        | justify | TNR         | 14    | 1.5     | 0        | 0        | 0          |
| `SUBHEADER`  | `Решение.`, `Скриншоты`, `Исходный код`      | justify | TNR         | 14    | 1.5     | 0        | 0        | 0          |
| `BODY`       | обычный текст                                | justify | TNR         | 14    | 1.5     | 0        | 0        | 0          |
| `CODE`       | код                                          | left    | Courier New | 12    | 1.0     | 0        | 0        | 0          |
| `LIST_ITEM`  | пункты выводов                               | justify | TNR         | 14    | 1.5     | 0        | 0.5 см  | −0.5 см   |

`TNR` = Times New Roman.
`Left` и `First line` — отступы в сантиметрах.
`LIST_ITEM` использует висячий отступ: номер сдвинут вправо на 0.5 см,
переносы строк — с отступом 1.0 см (как в Word/Google Docs).

## Типы блоков и как их определять

| Тип          | Признак                                                              |
|--------------|----------------------------------------------------------------------|
| `TITLE`      | все абзацы до первой `Задача`                                        |
| `SECTION`    | `startswith` `Задача` / `Выводы`                                     |
| `SUBHEADER`  | `startswith` `Решение.` / `Скриншоты` / `Исходный код`               |
| `LIST_ITEM`  | regex `^\d+\.\s`                                                     |
| `CODE`       | все абзацы между `Исходный код` и следующим `SECTION` / `SUBHEADER`  |
| `IMAGE`      | абзац содержит `w:drawing`                                           |
| `BODY`       | всё остальное                                                        |

## Правила пустых строк

Пустые абзацы **генерируются по правилам**, а не копируются из исходника.
Пустые абзацы входного документа игнорируются полностью.

| После чего                          | Пустая строка |
|-------------------------------------|---------------|
| Титульная часть                     | НЕТ           |
| `Задача N.` (SECTION)               | НЕТ           |
| `Решение.` (SUBHEADER)              | НЕТ           |
| `Скриншоты` (SUBHEADER)             | НЕТ           |
| Последняя картинка в группе         | **ДА**        |
| Код                                 | **ДА**        |
| Список выводов (последний пункт)    | **ДА**        |
| Всё остальное                       | НЕТ           |
